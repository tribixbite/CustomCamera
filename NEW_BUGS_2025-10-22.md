## Bug 1: PiP Photo Capture Shows Black Camera Feeds

### Symptoms
- PiP mode activates successfully
- Both camera previews visible on screen
- When tapping capture button:
  - Loading indicator appears
  - Background shows black camera feeds (both cameras)
  - Photo may or may not save

### Investigation Status
- **Code Location:** `CameraActivityEngine.kt` line 480-537 (photo capture)
- **Compositor:** `DualCameraCompositor.kt` (YUV to Bitmap conversion)
- **Spec:** `docs/specs/advanced-capture-features.md` (FR-12: Dual camera photo compositing)

### Potential Causes
1. **ImageProxy timing issue** - Main or PiP image not available when composite starts
2. **YUV conversion failure** - `imageProxyToBitmap()` returning null
3. **Preview freeze during capture** - Camera feeds stop updating during capture processing
4. **Buffer handling** - ImageProxy not being properly captured/converted

### Code Path
```
captureRegularPhoto()
  └─> Check: isDualCamera && dualCameraPiPPlugin != null (line 480)
      └─> imageCapture.takePicture() (line 483)
          └─> Get PiP frame: cameraEngine.getLatestPipFrame() (line 489)
              └─> DualCameraCompositor.compositeImages() (line 504)
                  └─> imageProxyToBitmap() for both cameras
                      └─> Convert YUV_420_888 to Bitmap
```

### Next Steps
1. Check logs for composite failures: `adb logcat -d | grep "DualCameraCompositor"`
2. Verify photo file is created: `adb shell run-as com.customcamera.app ls -lt files/ | grep CAMERA_ENGINE`
3. Check if main vs PiP image conversion fails
4. Test if issue is visual only or photo actually black

## Bug 2: Video Recording Fails with Sampling Rate Error

### Symptoms
- Tap video recording button
- Toast message: "failure to start recording. to use the sampling rate of..." (message cut off)
- Recording does not start

### Investigation Status
- **Code Location:** `CameraActivityEngine.kt` line 2289-2346 (toggleVideoRecording)
- **Plugin:** `AdvancedVideoRecordingPlugin.kt` line 145-222 (startRecording)
- **Error Display:** Line 2337 shows error message format

### Potential Causes
1. **Audio Configuration Mismatch**
   - Device audio profiles show sampleRate=48000 Hz
   - App may be requesting different sample rate
   - MediaRecorder audio config issue

2. **PiP Mode Conflict**
   - Video recording is **intentionally disabled** in concurrent camera mode (line 2307-2312)
   - Error message: "Video recording unavailable in PiP mode. Disable PiP to record video."
   - User may have been in PiP mode when testing

3. **Audio Permission**
   - Code checks RECORD_AUDIO permission (line 160-163)
   - Falls back to video-only if denied
   - But error suggests audio config issue, not permission

### Code Path
```
toggleVideoRecording()
  └─> Check plugin available (line 2291-2296)
  └─> Check if in concurrent mode (line 2305-2313) ❌ Returns if PiP active
  └─> Check VideoCapture available (line 2317-2327)
  └─> plugin.startRecording() (line 2331)
      └─> prepareRecording() with audio (line 167)
          └─> withAudioEnabled() (line 171)
              └─> MediaRecorder configuration
                  └─> ❌ Audio sampling rate error?
```

### Device Audio Capabilities

### Next Steps
